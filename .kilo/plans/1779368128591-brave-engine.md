# Implementation Plan: Server-Side Pagination for Admin Food Grid Page ("Lưới món ăn")

## 1. Current State Analysis

**Page in scope:**
- URL: `/admin/foods/grid`
- Controller: `AdminFoodController.grid(...)` (lines 206-227)
- Template: `src/main/resources/templates/admin/food-grid.html`
- Current behavior: Loads **all** foods (or all in one category) at once via `foodRepository.findAll()` / `findByCategory_CategoryId(...)` and renders with simple `th:each`. No pagination, no "Load More".

**Related existing code:**
- `FoodRepository` already exposes a paged method: `Page<Food> findByCategory_CategoryId(Long categoryId, Pageable pageable);`
- `JpaRepository` provides `findAll(Pageable)` out of the box.
- `CatalogueResponse.java` exists (prepared for load-more style responses).
- `admin.js` contains unused "Load More" skeleton code that calls `/admin/categories/load-more`.
- Pagination CSS classes already exist in `admin-style.css`: `.pagination-info`, `.pagination-btns`, `.page-btn`, `.active`.
- The sibling page `/admin/foods` (food-list.html) uses **client-side** JavaScript pagination (inline `<script>` — this violates the separation rule requested by the user).

**User requirements (explicit):**
- Add **phân trang** (pagination) to the grid page.
- **Strict file separation**: Do NOT put CSS or JavaScript inline in the HTML template. All new styles and scripts must live in dedicated files under `src/main/resources/static/css/` and `src/main/resources/static/js/`, following the project's admin naming conventions.

**Missing UI currently:**
- Although controller passes `categories` and `selectedCategoryId`, the template has no category filter dropdown or any filter UI.

---

## 2. Recommended Approach

**Use Server-Side Pagination with Spring Data `Pageable`**

**Why server-side (not client-side like the table view)?**
- Performance: Large catalogs will not send hundreds of food cards to the browser.
- Scalability: Standard pattern for admin product grids.
- Reuses the already-existing paged repository method.
- Avoids loading all data just to paginate on the client.

**Why not "Load More" (AJAX) right now?**
- User specifically asked for "phân trang".
- Classic numbered pagination is more discoverable and matches the existing table pagination UX.
- Load More code in `admin.js` + `CatalogueResponse` appears to be incomplete/planned work for the categories page and is not wired to the food grid.

**Alternative considered (documented for user decision):**
- If the user later prefers "Load More / Xem thêm" button with AJAX, we can switch to the existing `CatalogueResponse` pattern with minimal extra work.

**Page size recommendation:** 12 items per page (good visual fit for a 3- or 4-column card grid on most screens). Make it configurable in the future if needed.

**Additional UX improvements (minimal scope):**
- Add a simple category filter `<select>` on the page itself (currently missing).
- Preserve `categoryId` across page navigation.
- Reset to page 0 when category filter changes.
- Show "Hiển thị X–Y / Z món ăn" + numbered buttons (reuse existing CSS).

---

## 3. Detailed Implementation Steps

### Phase 1: Backend Changes (Controller + Minor Repository if needed)

1. **Update `AdminFoodController.java`** (method `grid`):
   - Add parameters:
     ```java
     @RequestParam(defaultValue = "0") int page,
     @RequestParam(defaultValue = "12") int size
     ```
   - Import `org.springframework.data.domain.*`
   - Create `Pageable pageable = PageRequest.of(page, size, Sort.by("foodId").descending());` (or any reasonable sort).
   - Change the food fetching logic:
     - If `categoryId != null` → use the existing paged repository method.
     - Else → use `foodRepository.findAll(pageable)`.
   - Map the `Page<Food>` to `Page<FoodDTO>` using `foodPage.map(foodMapper::toDTO)`.
   - Add to model:
     - `"foods"` → `dtoPage.getContent()`
     - `"foodPage"` → the `Page<FoodDTO>` object (so template can read `.totalPages`, `.number`, `.hasNext()`, etc.)
     - Keep `"categories"` and `"selectedCategoryId"`
   - Update method Javadoc.

2. **FoodRepository** (optional but clean):
   - The `findAll(Pageable)` is inherited from `JpaRepository<Food, Long>`, so no change needed.
   - If we want a cleaner search-with-pagination later, we can add a paged version of the `search(...)` method, but this is **out of scope** for this task.

3. **No changes** to `FoodDTO`, `FoodMapper`, or entities.

**File to edit:** `src/main/java/com/foodorderingsystem/controller/AdminFoodController.java`

---

### Phase 2: Template Updates (food-grid.html) – Keep it clean

1. **Override the `<head>`** (like `restaurant-form.html` does) to include a dedicated CSS file:
   ```html
   <head>
       <th:block th:replace="~{fragments/admin-layout :: admin-head}"></th:block>
       <link rel="stylesheet" th:href="@{/css/admin-food-grid.css}">
   </head>
   ```

2. **Add category filter UI** (inside the `<main>` after the page header, before `.catalogue-grid`):
   - A `<form>` or simple `<select>` that changes the URL (preserves current page=0 when category changes).
   - Use the existing `${categories}` and `${selectedCategoryId}`.

3. **Render the grid** exactly as before (no change to card HTML).

4. **Add pagination controls at the bottom** (after `.catalogue-grid`):
   - Container using existing classes: `.card-footer-pagination`, `.pagination-info`, `.pagination-btns`
   - "Hiển thị X–Y / Z món ăn"
   - Buttons: « Trước, numbered pages, Tiếp »
   - Use Thymeleaf to generate links:
     - `th:href="@{/admin/foods/grid(page=${foodPage.number-1}, size=${foodPage.size}, categoryId=${selectedCategoryId})}"` etc.
   - Handle edge cases (first page, last page, totalPages == 1 → hide pagination).

5. **Add the page-specific JS** at the very end (before `</body>`):
   ```html
   <script th:src="@{/js/admin-food-grid.js}"></script>
   </body>
   ```

**Important rule enforcement:**
- No `<style>` blocks.
- No `<script>` with logic (only the external include).
- All new logic goes into the external JS file.

**File to edit:** `src/main/resources/templates/admin/food-grid.html`

---

### Phase 3: New Dedicated Asset Files (Strict Separation)

Create two new files following project conventions:

1. **`src/main/resources/static/css/admin-food-grid.css`**
   - Purpose: Any grid-specific or pagination layout tweaks that are not generic enough for `admin-style.css`.
   - Initially can be mostly empty or contain:
     - Layout adjustments for the new filter bar
     - Responsive tweaks for the pagination on the grid page
     - (Optional) Make `.catalogue-grid` use CSS grid with better gap if needed
   - Import order: The page will load `admin-style.css` first via layout, then this file — so we can override safely.

2. **`src/main/resources/static/js/admin-food-grid.js`**
   - Purpose: Handle interactive behavior for the new filter and any future enhancements.
   - Minimal initial content:

     - When category changes → reset `page=0` and navigate (or submit a small form)

   - Keep it small and clean. Do not duplicate the big inline script from food-list.html.

**Naming justification:**
- `admin-food-grid.*` clearly indicates it belongs to the admin food grid page.
- Avoids conflict with the existing user-facing `food-grid.css` / `food-grid.js`.

## 6. Risks & Edge Cases to Handle

- Very long category names in the filter dropdown.
- Vietnamese text consistency ("Hiển thị", "Trước", "Tiếp", "món ăn").
- When there are exactly N × pageSize items, the last page should still work.
