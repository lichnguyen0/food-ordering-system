# Plan: Persistent Shopping Cart (Database-Backed)

## Current State Analysis
- Cart currently stored in **HttpSession only** (`CartApiController.getCart()`)
- No database persistence - cart lost on server restart/browser close
- `application.properties:28` has `server.servlet.session.persistent=false`

## Target Architecture (GrabFood/ShopeeFood style)
- **Database-backed cart** with MySQL as primary store
- **Session-backed cart** for unauthenticated users (with 30-day expiry)
- **User cart merge** when guest logs in
- Support cross-device persistence

## Phase 4: Controller Updates

### 4.1 CartApiController Changes
- `getCart()` now fetches from database:
  - If authenticated user: `cartRepository.findByUserId()`
  - If guest: `cartRepository.findBySessionId(session.getId())`
- Save cart to database on each modification:
  - `cartRepository.save(cart)` after add/remove/update
- Handle guest cart creation with expiry (30 days)

### 4.2 Cart Retrieval Logic
```java
private Cart getOrCreateCart(HttpSession session, String username) {
    if (user != null) {
        cart = cartRepository.findByUserIdAndStatus(user.getUserId(), ACTIVE);
        if (cart == null) cart = createNewCart(user.getUserId(), null);
    } else {
        String sessionId = session.getId();
        cart = cartRepository.findBySessionIdAndStatus(sessionId, ACTIVE);
        if (cart == null) cart = createNewCart(null, sessionId);
    }
    return cart;
}
```

## Phase 5: Session Listener for Merge

### 5.1 Login Event Handler

## Phase 6: Migration Strategy

### 6.1 Backward Compatibility
- First check database for existing cart
- If not found, check session (for upgrade path)
- Store cart to database before returning

### 6.2 Cart Expiry Cleanup
- Background job or TTL column for cleanup
- Delete carts older than 30 days

## Key Design Decisions

1. **Keep existing Cart/CartItem as DTOs** - used for JSON response and cart operations
2. **Separate Entity classes** - for JPA persistence
3. **Price snapshot** - store `unitPrice` at time of add (current `getUnitPrice()` logic)
4. **Guest cart expiry** - 30 days using `@TTL` or scheduled cleanup
5. **Restaurant conflict** - maintain current singleton cart per restaurant pattern (Swiggy-style)

---

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Existing session carts lost | Check session first, migrate to DB |
| Concurrent modification | Use `synchronized` on cart operations or optimistic locking |
| Large cart objects | Lazy load food details, only fetch when needed |
