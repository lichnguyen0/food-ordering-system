# Plan: Hiển thị thông báo "Vui lòng đăng nhập để đặt đơn" khi người dùng chưa đăng nhập bấm nút "+" thêm món

## Mục tiêu
Khi người dùng **chưa đăng nhập** bấm nút `+` (`.btn-quick-add`) trên trang chi tiết nhà hàng (menu), hệ thống phải hiện ra một modal đẹp thay vì im lặng thêm món vào giỏ:
- Tiêu đề: "Vui lòng đăng nhập"
- Nội dung: "Bạn cần đăng nhập để thêm món ăn vào giỏ hàng và đặt đơn."
- Nút: "Đăng nhập" (chuyển đến `/login`) và "Hủy"

## Phân tích nguyên nhân gốc rễ (Root Cause)
1. **Frontend không kiểm tra trạng thái đăng nhập**:
   - `restaurant-detail.html` (các dòng 158-166, 193-200, 230-237) render nút `<button class="btn-quick-add">` + `<div class="cart-quantity-controls">` cho mọi user.
   - `restaurant-detail.js:149-172`: `btnAdd.addEventListener('click')` luôn gọi `window.openOptionsOrAdd(...)` mà không kiểm tra auth.
   - `cart-sidebar.js:145`: Hàm `window.openOptionsOrAdd` là điểm tập trung xử lý thêm món (cả món đơn giản lẫn có options). Bên trong nó gọi ngay `fetch('/api/cart/add/...')` hoặc `fetch('/api/cart/add-with-options/...')`.

2. **Backend cho phép anonymous**:
   - `SecurityConfig.java:42`: `.requestMatchers(..., "/api/cart/**").permitAll()` → mọi người (kể cả guest) đều gọi được API giỏ hàng qua session.
   - `CartApiController.java`: Tất cả endpoint `/api/cart/*` đều hoạt động với `HttpSession` mà không yêu cầu `Principal`.

3. **Không có cơ chế chia sẻ trạng thái đăng nhập xuống JS**:
   - Header dùng `sec:authorize` (Thymeleaf + Spring Security) để hiện/ẩn nút "Đăng nhập", nhưng không expose biến JS nào như `window.isUserLoggedIn`.

4. **Không có modal hoặc guard nào cho trường hợp "login required"** (chỉ có `showCustomConfirmModal` cho conflict giỏ hàng).

Kết quả: unauthenticated user bấm `+` → API thành công im lặng → giỏ hàng session được tạo cho guest.

## Phạm vi ảnh hưởng
- **Chính**: Trang `user/restaurant-detail.html` + 2 file JS (`restaurant-detail.js`, `cart-sidebar.js`).
- **Phụ** (có thể hưởng lợi sau này):
  - Các trang khác nếu sau này dùng lại pattern `.cart-quantity-controls` + `openOptionsOrAdd`.
  - Nút "Tiến hành thanh toán" trong cart sidebar (`header.html:78`).
  - Trang cũ `food/food-list.html` (dùng link trực tiếp `/cart/add/{id}`) – mức độ thấp, có thể bỏ qua hoặc xử lý riêng.

## Giải pháp đề xuất (Client-side guard + Modal đẹp)

### 1. Inject trạng thái đăng nhập vào JS (global flag)
**File**: `src/main/resources/templates/fragments/header.html`

Thêm đoạn script ngay trước hoặc sau khi include `cart-sidebar.js`:

```html
<script th:inline="javascript">
    /*<![CDATA[*/
    window.isUserLoggedIn = /*[[${#authorization.expression('isAuthenticated()')}]]*/ false;
    /*]]>*/
</script>
```

- Ưu điểm: Nhẹ, không cần endpoint mới, hoạt động trên mọi trang vì header được include.
- Đặt biến này ở header đảm bảo nó có sẵn trước khi `cart-sidebar.js` và `restaurant-detail.js` chạy.

### 2. Tạo hàm modal "Yêu cầu đăng nhập" (tái sử dụng style hiện có)
**File**: `src/main/resources/static/js/cart-sidebar.js`

Thêm hàm mới (gần cuối file, sau `showCustomConfirmModal`):

```js
window.showLoginRequiredModal = function() {
    // Xóa modal cũ nếu có
    const existing = document.getElementById('loginRequiredModal');
    if (existing) existing.remove();

    const modal = document.createElement('div');
    modal.id = 'loginRequiredModal';
    modal.style.cssText = `...`; // giống hệt style của conflict modal (overlay + card)

    modal.innerHTML = `
        <div style="...">  <!-- card -->
            <div style="...icon..."><i class="fa-solid fa-lock"></i></div>
            <h3>Vui lòng đăng nhập</h3>
            <p>Bạn cần đăng nhập để thêm món ăn vào giỏ hàng và đặt đơn.</p>
            <div style="display:flex; gap:12px;">
                <button id="loginCancelBtn">Hủy</button>
                <button id="loginConfirmBtn">Đăng nhập</button>
            </div>
        </div>
    `;

    document.body.appendChild(modal);

    // Event handlers
    document.getElementById('loginCancelBtn').onclick = () => modal.remove();
    document.getElementById('loginConfirmBtn').onclick = () => {
        window.location.href = '/login';
    };

    // Fade-in + hover effects (copy từ conflict modal)
}
```

- Giữ nguyên design language (màu sắc, border-radius, button style) với modal conflict hiện tại để nhất quán.

### 3. Thêm guard tại điểm tập trung thêm món
**File**: `src/main/resources/static/js/cart-sidebar.js`

Ở đầu hàm `window.openOptionsOrAdd` (dòng 145):

```js
window.openOptionsOrAdd = function(foodId, foodName, price, image, desc) {
    if (!window.isUserLoggedIn) {
        showLoginRequiredModal();
        return;                    // ← Dừng ngay, không gọi API
    }
    // ... code cũ ...
};
```

Vì mọi luồng thêm món từ restaurant-detail đều đi qua hàm này, chỉ cần guard ở đây là đủ.

### 4. (Optional) Guard sớm ở restaurant-detail.js (defense-in-depth)
**File**: `src/main/resources/static/js/restaurant-detail.js`

Trong handler click `btnAdd` (dòng ~149), trước dòng gọi `openOptionsOrAdd`:

```js
btnAdd.addEventListener('click', function(e) {
    e.preventDefault();
    if (!window.isUserLoggedIn) {
        if (typeof window.showLoginRequiredModal === 'function') {
            window.showLoginRequiredModal();
        }
        return;
    }
    // ... phần còn lại ...
});
```

### 5. (Nice-to-have) Bảo vệ nút checkout trong cart sidebar
Trong `header.html`, thay đổi link checkout:

```html
<a href="/checkout" class="btn-checkout" onclick="return checkLoginBeforeCheckout(event)">
    Tiến hành thanh toán
</a>
```

Thêm hàm nhỏ trong `cart-sidebar.js`:

```js
window.checkLoginBeforeCheckout = function(e) {
    if (!window.isUserLoggedIn) {
        e.preventDefault();
        showLoginRequiredModal();
        return false;
    }
    return true;
};
```

### 6. Xem xét bảo vệ phía server (khuyến nghị sau này)
Hiện tại không bắt buộc cho task này, nhưng nên ghi nhận:

- Có thể tạo endpoint nhẹ `GET /api/auth/status` trả về `{ loggedIn: true/false, username: "..." }`.
- Hoặc sau này khi muốn enforce chặt:
  - Đổi SecurityConfig: bỏ `permitAll()` cho `/api/cart/**`, yêu cầu `authenticated`.
  - Xóa logic giỏ hàng session cho guest.
  - Sửa `OrderController.checkout()`: bỏ fallback `userId = 1L`, bắt buộc `principal != null`.

## Kiểm thử (Test cases)

1. **Chưa đăng nhập**:
   - Vào trang chi tiết nhà hàng → bấm `+` bất kỳ món nào → hiện modal "Vui lòng đăng nhập".
   - Bấm "Hủy" → modal đóng, không có item nào được thêm.
   - Bấm "Đăng nhập" → chuyển hướng `/login`.

2. **Đã đăng nhập**:
   - Bấm `+` → hành vi cũ (thêm món, mở options nếu có, cập nhật badge header) không thay đổi.

3. **Giỏ hàng trống + chưa login**:
   - Mở cart sidebar → nút "Tiến hành thanh toán" (nếu click) cũng hiện modal.

4. **Sau khi login từ modal**:
   - User được redirect về trang trước (hoặc trang login có `?redirect=...` nếu implement sau).
   - Sau login thành công → có thể bấm `+` bình thường.

5. **Regression**:
   - Tất cả flow thêm món, tăng/giảm số lượng, options, conflict modal vẫn hoạt động như cũ khi đã login.

## Lưu ý khi implement
- Giữ nguyên tên hàm `showLoginRequiredModal` và expose ra `window.` để các file JS khác có thể gọi.
- Không thay đổi logic backend CartApiController trong phase này (tránh ảnh hưởng session cart hiện có).
- Modal phải responsive và đẹp trên mobile (copy style từ conflict modal đã test tốt).
- Đảm bảo không có lỗi console khi `window.isUserLoggedIn` chưa được define (dùng `|| false`).
