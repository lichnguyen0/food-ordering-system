# Pagination Implementation Plan for Admin Orders Page

## Current State
- Admin orders page loads all orders without pagination
- Controller: AdminController.orders() calls orderService.getAll() → returns List<Order>
- Service: OrderServiceImpl.getAll() returns orderRepository.findAllByOrderByOrderIdDesc()
- Template: Uses th:each to iterate over full lists for each status tab

## Goal
Implement pagination for all order tabs (Pending, Processing, Shipping, Completed) to improve performance with large datasets.

## Solution Approach
Apply pagination at the repository level with status-based filtering for each tab:
1. Add paginated repository methods for each order status group
2. Update service layer to expose paginated methods
3. Modify controller to accept page/size parameters and return Page objects
4. Update template to display paginated results and pagination controls

## Detailed Changes

### 1. Repository Updates
**File:** src/main/java/com/foodorderingsystem/repository/OrderRepository.java
- Add method: `Page<Order> findByStatusIn(List<OrderStatus> statuses, Pageable pageable);`
- Add method: `Page<Order> findByStatus(OrderStatus status, Pageable pageable);` (for simple statuses)
- Note: OrderRepository likely extends JpaRepository<Order, Long> which already provides findAll(Pageable)

### 2. Service Layer Updates
**File:** src/main/java/com/foodorderingsystem/service/OrderService.java
- Add methods:
  - `Page<Order> getPendingOrders(Pageable pageable);`
  - `Page<Order> getProcessingOrders(Pageable pageable);`
  - `Page<Order> getShippingOrders(Pageable pageable);`
  - `Page<Order> getCompletedOrders(Pageable pageable);`

**File:** src/main/java/com/foodorderingsystem/service/impl/OrderServiceImpl.java
- Implement new methods using repository queries:
  - Pending: status = PENDING
  - Processing: status IN (PREPARING, CONFIRMED)
  - Shipping: status = DELIVERING
  - Completed: status IN (DELIVERED, CANCELLED)

### 3. Controller Updates
**File:** src/main/java/com/foodorderingsystem/controller/AdminController.java
- Modify orders() method:
  - Add parameters: 
    - `@RequestParam(defaultValue = "0") int page`
    - `@RequestParam(defaultValue = "10") int size`
  - Create Pageable object: `Pageable pageable = PageRequest.of(page, size, Sort.by("orderId").descending());`
  - Call service methods for each status tab to get Page<Order> objects
  - Add Page objects to model (e.g., model.addAttribute("pendingOrdersPage", pendingPage))
  - Keep current tab counts for badge display (may need separate count queries or use Page.getTotalElements())

### 4. Template Updates
**File:** src/main/resources/templates/admin/orders.html
- Replace th:each iterations with:
  - `th:each="order : ${pendingOrdersPage.content}"` for pending tab
  - Similar for other tabs
- Add pagination controls below each tab content:
  - Display current page / total pages
  - Previous/Next page buttons (disabled when applicable)
  - Page size selector (optional)
- Ensure tab switching preserves pagination state (may need to include page in tab data or use separate pagination state)

### 5. Additional Considerations
- Update AJAX status update method to work with paginated views (currently reloads entire page)
- Consider whether to maintain current tab badge counts (total per status) or show paginated counts
- Ensure sorting is consistent (currently by orderId descending)

## Implementation Order
1. Update repository interface
2. Update service interface and implementation
3. Modify controller
4. Update template
5. Test all tabs and pagination controls
