# Plan to Fix Save Button in Admin Food Form

## Goal
Fix the "Save" button in the admin food form so that it properly submits the form, saves the food item, and redirects to the admin foods list page (/admin/foods).

## Current Status
- The button has been updated to `type="submit"` with `name="action" value="save"`.
- The controller has been updated to handle the "action" parameter and redirect based on it.
- User testing results:
  - Page reloads when clicking "Save" (form submits).
  - No console errors.
  - App has been restarted.
  - When required fields are filled, page reloads but doesn't save/redirect to list.
  - When fields are not filled, likely shows validation errors.
  - "Save and Add" button also doesn't work (same behavior).

## Investigation Steps
1. **Check Network Tab**: In browser dev tools, inspect the POST request to /admin/foods/save. Check response status (should be 302 redirect if successful, or 200 with form if validation fails).
2. **Server Logs**: Check application logs for any exceptions during save (e.g., database errors, mapping issues).
3. **Add Debug Logging**: Temporarily add System.out.println or logger statements in controller to confirm method execution and parameter values.
4. **Verify Mapping**: Ensure FoodMapper.toEntity() works without errors.
5. **Check Repository**: Confirm FoodRepository.save() succeeds (no constraint violations).
6. **Inspect Redirect**: If redirect happens, ensure /admin/foods URL is correct.

## Possible Causes
- **Server Exception**: An error in controller (e.g., mapping failure, DB save error) causes the request to fail silently or return to form.
- **Incorrect Redirect URL**: The redirect URL might be wrong or not resolving properly.
- **Security/Filter Issues**: Spring Security or filters blocking the POST request.
- **Data Binding Failure**: Parameters not binding correctly, causing method not to execute properly.
- **Validation Passing but Logic Failing**: Validation ok, but save or redirect logic has bug.

## Proposed Fixes
1. **Add Logging in Controller**: Wrap the save logic in try-catch, log entry/exit, parameters, and exceptions.
2. **Check Network Response**: Use browser network tab to see exact response from /admin/foods/save.
3. **Verify Redirect**: Temporarily change redirect to a simple string return to test if save works.
4. **Inspect Logs**: Run app with debug logging enabled to see detailed output.
5. **Test with Minimal Data**: Use simplest valid data to isolate issues.
